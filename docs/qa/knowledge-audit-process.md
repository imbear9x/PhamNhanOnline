# Knowledge Audit Process

## Goal

Audit whether project knowledge is discoverable, current, and grounded.

## Audit steps

1. Pick scope.
2. Inventory canonical docs and legacy docs.
3. Check frontmatter completeness.
4. Verify sample claims against code/runtime.
5. Record drift and gaps.
6. Publish an audit report.

## Outputs

- audit report in `docs/qa/`
- conflict reports in `docs/conflicts/` when needed
- follow-up change notes if the audit drove structural changes
