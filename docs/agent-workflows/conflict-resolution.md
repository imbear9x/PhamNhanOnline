# Conflict Resolution Workflow

## Trigger

Use this when docs, code, DB reality, or runtime behavior conflict.

## Process

1. Capture the mismatch in `docs/conflicts/`.
2. Link both sides of the evidence.
3. State impact clearly.
4. Recommend whether docs should change, code should change, or both.
5. Do not quietly rewrite the losing side unless explicitly implementing the resolution.

## Output

- conflict report
- optional change note or ADR if the fix changes policy
