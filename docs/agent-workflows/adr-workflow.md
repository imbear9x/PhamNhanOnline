# ADR Workflow

Use ADRs for decisions that are hard to reverse, affect multiple systems, or explain why the project chose one durable direction over another.

## Create an ADR when

- architecture changes cross module boundaries
- a rule constrains future implementation
- a tradeoff should be preserved for future agents

## Do not use ADRs for

- tiny refactors
- temporary experiments
- implementation notes that do not contain a durable decision
