# Config Contract Workflow

Use this workflow for config tables, server configs, data-driven mechanics, and shared parameter definitions.

## Rules

- document the source of truth explicitly
- separate field definition from gameplay interpretation
- include validation and consumer paths
- when contract and runtime differ, file a conflict report

## Minimum output

- one config contract doc in `docs/data-design/config-contracts/`
- related verification note or change note when needed
