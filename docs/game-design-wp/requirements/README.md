# Requirements

Use this folder for coder-ready design requirements with clear acceptance criteria.

## Rules

- Use `../templates/requirement-spec-template.md` for requirement specs.
- A requirement spec is the highest-maturity live primary doc for a system.
- Do not keep the source feature after promotion; migrate it into the requirement doc and delete it.
- Do not create duplicate requirements for the same `system_id`.
- New design decisions for an implementation-ready system should update the requirement doc directly unless they are audit/code clarification artifacts.

See `../DOC_LIFECYCLE.md`.
